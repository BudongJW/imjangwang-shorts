# 영상 개선 실험 고리

성과 데이터로 영상을 계속 고쳐 나가는 장치다. 사람이 감으로 바꾸지 않고,
한 번에 한 가지씩 바꿔 보고 숫자로 판정한다.

## 도는 순서

1. **제작** (매일 11:00 KST): `src/experiments.py`가 오늘 날짜로 각 실험의
   팔(arm)을 정한다. 영상은 그 팔대로 만들어지고, `topic_history.json`에
   영상별 팔이 `exp`로 남는다.
2. **분석** (매일 02:17 KST, `scripts/analyze_performance.py`): 영상마다
   같은 나이에서 잰 값을 팔별로 모은다.
   - 게시 48시간 조회수 (스냅샷 사이를 직선으로 이어 읽음)
   - 첫 화면 통과율 (engagedViews ÷ views)
   - 평균 시청률 (averageViewPercentage)
3. **판정**: 팔마다 10편이 모이면 두 팔 중앙값 차이의 90% 구간을 구한다.
   - 구간이 0을 넘지 않으면: 이긴 쪽을 기본값으로 굳힌다.
   - 20편씩 모여도 갈리지 않으면: 차이 없음, 지금 쓰는 쪽 유지.
4. **다음 실험**: 끝난 실험의 칸에 대기 중인 실험을 다음 날부터 연다.

상태는 `output/experiments_state.json`에 있고, 분석 워크플로가 master에
올린다. 리포트의 `## 실험 현황`에서 진행 상황을 본다.

## 날짜로 배정하는 이유

하루 한두 편이라 영상 단위로 섞으면 같은 날 영상끼리 조건이 갈린다.
동시에 세 실험까지 돌리고 칸을 나눈다.

| 칸 | 바뀌는 주기 |
|---|---|
| 0 | 하루씩 번갈아 |
| 1 | 이틀씩 번갈아 |
| 2 | 나흘씩 번갈아 |

여드레면 세 실험의 여덟 조합이 한 번씩 나와서 서로 효과가 섞이지 않는다.

칸 x01은 칸 0과 칸 1의 엇갈림이다(둘 중 하나만 1이면 1). 11-19에 칸 셋이 찬 채
질문형 제목 실험을 바로 열면서 만들었다. 나흘마다 두 팔이 두 번씩 나오고, 칸 0·1·2
어느 실험과도 조합이 고르게 나온다.

질문형 제목 on 팔인 날 지정 대본을 쓸 때는 youtube_title을 물음표로 끝나는 시청자 입장
질문(25자 안팎, 따옴표 없이)으로 쓰고, caption_script 첫 문장도 같은 질문으로 시작한다.
그날 팔은 `python -c "from src.experiments import arm; print(arm('title_q', '2026-11-20'))"`.

## 실험 목록 (위에서부터 차례로)

| 실험 | 비교 | 판정 지표 | 시작 |
|---|---|---|---|
| 대본 길이 | 48~55초 / 31~37초 | 48시간 조회수 | 10-02 |
| 첫 화면 숫자 카드 | 켬 / 끔 | 첫 화면 통과율 | 10-04 |
| 숫자 구간 배경 | 사진 위 카드 / 남색 정보 화면 | 평균 시청률 | 10-10 (칸 2) |
| 끝맺음 질문 | 없음 / 시청자에게 질문 | 게시 48시간 조회수 (좋아요 비율 같이 봄) | 대기 (다음 빈 칸) |
| 질문형 제목 | 질문형 제목·첫 문장 / 기사 헤드라인형 | 게시 48시간 조회수 (통과율·좋아요 같이 봄) | 11-20 (칸 x01) |
| 기사 화면 위치 | 첫 컷 뒤(3~8초) / 영상 중간 | 평균 시청률 (첫 화면 통과율 같이 봄) | 대기 (끝맺음 질문 다음) |
| 배경음 | 켬 / 끔 | 평균 시청률 | 대기 |
| 컷 길이 | 3초 / 2초 | 평균 시청률 | 대기 |

지정 대본(사람이 쓴 대본)은 길이 실험에서만 뺀다. 나머지 실험에는 넣는다.
끝맺음 질문 팔인 날에는 제작 단계(`src/orchestrator/main.py`의 `_apply_outro_arm`)가 지정
대본 끝에도 짧은 질문을 붙인다. 지정 대본을 쓸 때 질문을 직접 넣어도 된다.
자동 초안의 사실만 고친 지정 대본은 `keep_len_arm`을 켜면 길이 실험에도 들어간다
(글자 수가 그날 팔 범위일 때만).

기사 화면 위치 실험의 근거는 구간별 시청 유지다. 3초에 남아 있던 시청자의 40%가
8초 전에 떠나는데(10-10판 9편 중앙값, 11-10 리포트), 그 5초가 글자만 있는 기사 화면이고
그 동안에는 숫자 카드를 띄우지 못한다. late 팔은 기사 화면을 배경 컷의 45% 지점으로
옮기고, 비워 둔 첫 화면(0~2.6초) 바로 뒤에 첫 문장의 숫자 카드를 띄운다. 미리 보려면
`python scripts/preview_render.py <지정 대본> --arm article_pos=late`.

## 화면 구성 판

실험과 따로, 화면 구성을 통째로 바꾼 날은 판(`LAYOUT_VERSION`, `src/editor/composer.py`)을
올린다. 영상마다 `topic_history.json`의 `layout`에 남고, 분석 리포트의 구간별 시청 유지가
판마다 따로 모인다.

| 판 | 바뀐 것 |
|---|---|
| 2026-10-10 | 기사 화면(캡처 윗부분 + 강조 문장), 숫자 카드 이름표, 자막 묶음 규칙 |
| 2026-11-10 | 첫 자막 0초부터, 나레이션 앞 무음 제거, 자막 숫자 강조 단위 |
| 2026-11-25 | 움직임 묶음(`src/editor/motion.py`) |
| 2026-11-26 | 이름표(`src/editor/lower_third.py`), 기사 화면 강조 문장이 한 줄씩 나타남 |

### 2026-11-25 움직임 묶음

조회수 중앙값이 9월 상반기 1,181회에서 11월 하반기 23회로 내려갔고, 화면이 틀 하나로
50초 동안 고정돼 슬라이드 쇼처럼 보였다. 내용과 배치는 그대로 두고 움직임만 넣었다.

| 요소 | 전 | 후 |
|---|---|---|
| 자막 | 구절이 통째로 켜졌다 꺼짐 | 구절이 튕기며 뜨고, 말하는 어절이 차례로 밝아짐(숫자의 노랑은 그대로) |
| 숫자 카드 | 켜졌다 꺼짐 | 튕기며 커졌다가 흐려지며 사라짐. 정보 화면 팔은 옆에서 밀려 들어옴 |
| 비교 카드 | 다 자란 막대 | 막대가 바닥에서 0.5초 동안 자람(값 글자는 처음부터 대본 값) |
| 배경 컷 | 가운데 줌 인·아웃만 | 줌에 좌우·상하 팬을 섞고, 컷이 바뀔 때 짧게 당겼다 놓음 |
| 기사 화면 | 4~5초, 뚝 바뀜 | 3~3.5초, 아래에서 밀려 올라왔다 내려감(11-26판부터 강조 문장이 한 줄씩 나타남) |
| 제목 배너 | 처음부터 강조어 노랑 | 0.45초에 강조어가 노랗게 켜짐(제목은 첫 프레임부터 있음) |

근거로 삼은 것(같은 날 레퍼런스 조사):

- WSJ·KBS 크랩의 쇼츠는 첫 1.5초 안에 제목 글자가 쳐지고, 그래픽이 한 칸씩 쌓이며 나타난다.
  요소가 '나타나는 과정'이 보인다.
- 한국 상위 뉴스·경제 채널(스브스뉴스, 14F, 크랩, 삼프로TV 등)은 위에 2줄 제목 띠(강조어
  노랑), 가운데 영상, 아래 구절 단위 자막이다. 이 채널의 배치와 같아서 배치는 건드리지 않았다.
- 글자만 있는 장면은 짧을수록 낫다는 쪽이 이 채널 자체 수치와 맞는다(위 기사 화면 위치 실험의
  근거 참고).

넣지 않은 것: 효과음, 진행 막대, 숫자 세어 올리기, 더 빠른 컷. 조사에서 근거를 찾지 못했거나
(효과음·진행 막대) 반대 자료가 있었다(컷 속도). 숫자 세어 올리기는 기사에 없는 수가 화면에
지나가므로 하지 않는다. 컷 길이는 대기 중인 실험이 따로 있다.

실험과의 관계: 판은 모든 팔에 같은 날 똑같이 들어가므로 팔끼리 비교는 치우치지 않는다. 다만
11-25 앞뒤 표본이 한 팔 안에 섞여 흩어짐이 커진다. 판 자체의 효과는 팔 비교가 아니라 리포트의
판별 구간 시청 유지와 첫 화면 통과율로 본다.

끄기: 리포지터리 변수 `MOTION_FX=0`(또는 환경 변수). 그러면 판 값도 `2026-11-10`으로 남는다.
미리 보기: `python scripts/preview_render.py <지정 대본> --frames`, 끈 화면은 `--no-motion`.

### 2026-11-26 이름표와 기사 화면

움직임 묶음 다음 날 넣었다. 11-25판으로 만든 영상이 나오기 전에 합쳐졌다면 11-25판 표본은 없다.

| 요소 | 뜨는 때 | 화면에 쓰는 말 |
|---|---|---|
| 발언 이름표 | "○○ 소장은 …라고 말했습니다"처럼 말을 옮긴 문장을 읽는 동안 | 문장 머리의 이름·직함 그대로 |
| 출처 이름표 | "△△에 따르면 …" 문장을 읽는 동안 | '에 따르면' 앞의 말 그대로 |
| 임장왕 체크 | 시청자가 확인할 일을 짚는 문장("…부터 확인하세요", 대본 규칙 7) | `임장왕 체크` |
| 임장왕의 해석 | 진행자 본인의 읽기("저는 …로 봅니다", 대본 규칙 16) | `임장왕의 해석` |
| 기사 화면 | 기사 화면이 밀려 들어온 뒤 | 강조 문장이 한 줄씩 왼쪽에서 닦이듯 나타남 |

왜 넣었나:

- 대본은 말한 사람과 출처를 밝혀 쓰는데(규칙 13·15) 화면에서는 그 문장도 다른 문장과 같은 자막
  한 줄이었다. 누구 말인지가 따로 뜨면 소리 없이 보는 사람도 구분한다. WSJ 쇼츠는 말하는 사람
  이름이 아래에서 밀려 들어온다(11-25 레퍼런스 조사).
- 유튜브 수익화 정책이 "남이 쓴 글을 그대로 읽는 것", "틀에 박힌 콘텐츠"를 명시한다. 이 채널은
  이미 규칙 6·7·16으로 자체 해석과 실전 시사점을 대본에 넣고 있지만 화면에서는 기사를 읽는 대목과
  갈리지 않았다. '임장왕 체크'는 새 문장을 만들지 않고 이미 있는 그 대목을 드러낸다.
- 기사에 따라 뜨는 요소가 달라진다(발언이 많은 기사는 이름표, 통계 기사는 숫자 카드). 영상마다
  같은 틀이 반복되던 것이 내용에 따라 갈린다.

이름을 잘못 집지 않게 한 것:

- 문장 머리가 직함(교수·소장·장관 …)이나 기관(부동산원·국토부·LH …)으로 끝나고, 문장이 "…다고
  말했습니다" 꼴로 끝날 때만 '발언'으로 본다. "서울 아파트값은 …했다고 부동산원은 밝혔습니다"처럼
  말한 사람이 문장 머리가 아니면 띄우지 않는다.
- 한 문장에 말한 사람이 둘이면 앞사람의 이름표는 뒷사람이 나오기 전에 내린다.
- 지난 지정 대본 81편에 돌려 보니 51편에서 70개가 잡혔고(발언 35, 출처 11, 해설 24) 틀린 이름은
  없었다. 규칙은 `tests/test_lower_third.py`에 실제 문장으로 남겼다. 새로 틀린 꼴이 나오면 그
  문장을 `NO_TAG`에 한 줄 더한다.
- 무엇이 언제 떴는지는 `build_notes.txt`의 `이름표` 줄에 남는다. 검수할 때 같이 본다.

끄기: 이름표만 끄려면 리포지터리 변수 `NAME_TAGS=0`. `MOTION_FX=0`이면 이름표와 기사 화면 연출도
같이 꺼진다.

## 실험 추가하는 법

1. `src/experiments.py`의 `REGISTRY` 끝에 항목을 넣는다(key, 팔 두 개,
   대조군, 판정 지표).
2. 제작 코드에서 `arm("key")`로 팔을 읽어 분기한다.
3. 상태 파일은 손대지 않아도 된다. 새 항목은 대기로 붙고 차례가 오면 열린다.

## 손으로 멈추거나 되돌리기

`output/experiments_state.json`에서 해당 실험의 `status`를 바꿔 master에
올린다.

- 멈춤: `"queued"` (대조군으로 돌아감)
- 판정 무르기: `"running"`으로 되돌리고 `winner`·`verdict`를 지운다.
