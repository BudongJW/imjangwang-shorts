# 대본 길이 실험 (48~55초 → 31~37초)

## 왜

지속률이 잡힌 영상 20개(2026-09-13 기준) 상관계수:

- 길이 ↔ 지속률 **-0.52**
- 지속률 ↔ 조회수 **+0.68**
- 길이 ↔ 조회수 **-0.45**

짧을수록 지속률이 오르고, 지속률이 조회수를 만든다. 그런데 **관측된 길이가
45~92초뿐**이라 45초 미만이 더 나은지는 데이터가 없다. 이 실험은 그 빈 구간을
직접 재본다.

## 무엇을 바꾸나

`SCRIPT_LEN_MODE` 하나. 그 외에는 **아무것도 바꾸지 않는다.**

| 모드 | 목표 | 상한 | 환산(6.4자/초) |
|---|---|---|---|
| `normal` (기본) | 310~350자 | 380자 | 48~55초 |
| `short` (실험) | 200~240자 | 270자 | 31~38초 |

프리셋은 `config/settings.py`. 자막 크기·콜아웃·타이틀카드·게시 시각은
그대로 둔다. 둘을 같이 바꾸면 어느 쪽이 효과를 냈는지 못 가린다.

## 켜는 법

리포지터리 변수 하나:

```
gh variable set SCRIPT_LEN_MODE --body short
```

끌 때는 `gh variable set SCRIPT_LEN_MODE --body normal` (또는 변수 삭제).
워크플로가 `vars.SCRIPT_LEN_MODE`를 읽어 넘긴다.

## 켜기 전에: 렌더 눈으로 확인

변수를 켜면 다음 크론부터 바로 실제 업로드다. 그 전에 한 번 렌더만 돌린다.

```
git push origin master:run/daily-verify-short-0920
```

브랜치 이름 규칙 세 개가 동시에 걸린다.

- `run/daily-*` → 워크플로 트리거
- `...verify...` → `--skip-upload` (업로드 안 함)
- `...short...` → 변수와 무관하게 이번 실행만 `short`

끝나면 `verify-frames` 아티팩트에서 확인할 것:

- `build_notes.txt`의 `대본 길이 모드: short (200~240자, 상한 270자)`
- 대본이 문장 중간에서 끊기지 않았는지 (`_trim_incomplete_tail`)
- 수치 콜아웃이 **3개 이상** 뜨는지 — 220자에 수치 3개는 빡빡하다.
  1~2개로 떨어지면 화면 중앙이 비는 시간이 길어져 실험 자체가 오염된다.
- 자막이 잘리거나 겹치지 않는지

## 판단 기준

- **최소 7편**을 모은 뒤에 본다. 그 전에는 결론 내지 않는다.
- 비교는 `python scripts/analyze_performance.py` 의 **"길이 실험" 섹션**.
  코호트는 날짜가 아니라 `topic_history.json`의 `len_mode`로 가른다
  (크론이 하루 실패하거나 수동 재업로드가 끼면 날짜 경계는 무너진다).
- 보는 값: **지속률 중앙값**이 먼저고 조회수 중앙값이 그다음이다.
  조회수는 소재 운을 많이 타고, 지속률이 조회수를 만드는 쪽이다.
- 24시간 안 된 영상은 판단에서 뺀다 (`MIN_AGE_H_FOR_VERDICT`).

## 되돌리기

지속률이 normal보다 낮으면 `SCRIPT_LEN_MODE`를 `normal`로 되돌린다.
코드 롤백은 필요 없다 — 프리셋은 남겨 두고 변수만 되돌리면 된다.
